# Security audit — PlanTravel itinerary planner

**Date:** 2026-10-24 · **Auditor:** Claude (owner-reviewed) · **Commit:** branch `ccr-842b3a88-ddan6t` · **Target:** local `astro dev` with auth env + production build
**Overall posture:** before 🔴 high risk (open write API) -> after 🟠 medium (3 dependency majors outstanding)

## 1. Scope & method
Surface: 8 pages, 7 API handlers (`itinerary`, `place`, `sheets-sync`, `geocode`, `prayer-times`, `currency-exchange`, `logout`), Google Sheets read/write client, outbound hosts (Open-Meteo, AlAdhan, open.er-api, jsDelivr, Google Fonts, YouTube).
Methods: code read, `grep`, history secret search, `npm audit --omit=dev`, curl against a running server.
Not tested: real Google Sheets round trips (no credentials in this environment), Vercel runtime, PDF export.

## 7. Residual risk
- Without `EDITOR_PASSWORD` + `AUTH_SECRET`, production **cannot edit** (503). Safe but visible: set them before announcing.
- One critical advisory (`astro` 5) remains until the Tailwind 4 + Astro 7 migration lands. CI's audit job is advisory (non-blocking) for this repo until then.
- Public indexing: `sitemap.xml` lists every trip page. If trips are personal, drop the sitemap or add `noindex` before sharing the URL.
- Real sheet writes, PDF export and the signed-in editing UI were not exercised end to end (no Google credentials here).
