# v0.3.0: titled multi-city trips, copy and suggestions, and a consistent UI

Minor release. Backward compatible: **no new environment variables, no data migration, every old link keeps working.** It brings the trips redesign (PRs #40 to #44) and the UI standard series (#45 to #48).

## 🧳 Trips
| | |
|---|---|
| Titled trips | A trip has its own title ("AirTravel Sdn Bhd Trip at Japan 2025"), a stable address `/trips/<slug>` and can run through several cities (days 1-4 Tokyo, 5-7 Osaka). Two Japan trips in different years no longer merge. |
| Create and edit | New-trip wizard: Where, When, Cities, Review. The pencil on a trip edits **title, dates and cities** afterwards; places already in the itinerary are never moved or deleted. A City row appears in Add/Edit place for multi-city trips. |
| Start from | ✍️ From scratch, 📋 **Copy a trip** (whole or picked days, shifted to new dates, prices optional) or 💡 **Suggestions** (places other trips used, ranked, spread over your days). |
| Old links | Every `Country - State` tab is an automatic trip with its old address; `/japan/tokyo[/...]`, `/tools`, `/prepare` redirect (301); the old calendar feed keeps serving. |
| Country view | Lists the country's trips; it and every trip have the floating tab dock (more transparent). The Pocket ⋯ menu is no longer hidden behind the next section. |

## 🎨 UI standard
| | |
|---|---|
| Tokens | `danger` / `success` / `warning` colours (night-aware) and one smallest text size (11px) replace about 100 raw colour classes and 83 tiny-text uses; a test keeps it that way. |
| UI kit | One `Button`, `InlineError` (with Retry), `EmptyState`, toast (with Undo) and `apiFetch` replace hand-rolled copies. |
| Loading | One skeleton style; list skeletons shaped like real rows; the suggestions list dims instead of blanking while filtering. |
| Feedback | Deleting a place or Pocket item can be **undone** from the toast; saves and trip changes confirm with a toast. |
| Errors | A `500` page that never reads the sheet; home tells "no trips yet" from "can't reach your sheet"; no more `alert()`. |
| Tap targets | Footer links and map pins reach 44px. |

## ⚠️ Sheet changes (additive, automatic)
- Hidden `_trips` tab: registry columns K:Q (`title, slug, country, stops, created_by, created_at, copied_from`), written on the first trip create/copy/edit. Old rows are untouched.
- Optional `city` and `country` columns are added to a trip tab only when first used.
- If you roll back, those extra columns are simply ignored by v0.1.1.

## Not verified / limits
- Writes (create, copy, edit, undo) were tested with the dev sample data and intercepted requests, **not against the real sheet with a signed-in session**: do the preview checklist below before promoting.
- A trip is listed under one (primary) country, and Pocket tools keep one saved place per trip (the first city).
- Undo restores a place or Pocket item as a **new** row/id at the same day and time.
- `npm audit --omit=dev`: 4 moderate findings, all in the build-time chain `@astrojs/vercel` > `@vercel/nft` > `glob` / `minimatch`. They do not run on requests, and the only fix is a breaking `@astrojs/vercel` upgrade, so it is left for a separate change.

## Preview checklist (signed in, real sheet)
1. Create a two-city trip; open it; add a place in the second city (City row); edit title, dates and cities.
2. Copy a trip (whole, then two picked days with a new start date); build one from suggestions. Check `_trips` K:Q, dates and `copied_from`.
3. Delete a place, tap Undo; delete a Pocket item, tap Undo.
4. Open an old `/japan/tokyo` link (redirects) and the calendar feed.
5. As a guest: trips open, writes return 401. `npm run smoke -- <preview-url>` is green.
6. Break the sheet credentials on the preview and confirm the 500 page and the home "can't reach your sheet" message.

## Upgrade and rollback
- Upgrade: deploy as usual (preview first). No env or schema work.
- Rollback: revert the merge commit(s); tabs and rows created in 0.3.0 stay valid data.
